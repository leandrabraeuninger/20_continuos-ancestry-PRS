# Simulated genotype + ancestry + covariate dataset

Generated by `run_simulation.py` (full source included). Re-runnable and
re-parameterizable — see `simulation_config.json` for exact parameters used,
and the `src/` scripts for the underlying model.

## Files

| File | Description |
|---|---|
| `genotypes.bed/.bim/.fam` | Standard PLINK 1 binary fileset. Readable by PLINK, GCTA, `pandas-plink`, `bed-reader`, R `genio`/`snpStats`, etc. |
| `metadata.csv` | One row per individual: demographics, true ancestry, self-reported ethnicity, phenotype. |
| `snp_info.csv` | One row per SNP: position, alleles, per-population allele frequency, causal-SNP flag/effect size. |
| `simulation_config.json` | Exact parameters used for this run (for reproducibility). |

`individual_id` in `metadata.csv` matches the IID/FID in `genotypes.fam`, in
the same row order as `genotypes.bed`. `snp_id` in `snp_info.csv` matches
`genotypes.bim`, same order as the SNP axis of `genotypes.bed`.

## Population genetic model (how genotypes were generated)

1. **Ancestral allele frequencies** — one per SNP, drawn from a Beta(0.5, 0.5)
   distribution (a standard choice that gives a realistic U-shaped MAF
   spectrum: many common variants, many rare variants, few mid-frequency).
2. **Population-specific allele frequencies** — for each of the 5 ancestral
   populations, drawn from the **Balding-Nichols model**:
   `p_pop ~ Beta(p_anc(1-Fst)/Fst, (1-p_anc)(1-Fst)/Fst)`.
   This is the standard population-genetics way to parameterize
   differentiation between populations by Fst (here Fst = 0.05, roughly in
   the range of real human continental-level differentiation, which is
   typically cited around 0.05–0.15 depending on which populations and
   markers are compared).
3. **Individual admixture proportions** — each individual's true ancestry is
   a continuous vector over the 5 populations, drawn from a
   **Dirichlet(alpha)** distribution (the standard PSD/STRUCTURE/ADMIXTURE
   model). `alpha = 0.3` here, which produces a mix of mostly-unadmixed and
   meaningfully-admixed individuals — not just 5 discrete clusters.
4. **Genotypes with linkage disequilibrium** — SNPs are grouped into blocks
   of 50. For each individual, each haplotype, each block, a single source
   population is drawn from that individual's admixture proportions; every
   SNP in that block on that haplotype is then drawn from that population's
   allele frequency. This is a lightweight block-bootstrap approximation
   (similar in spirit to HAPGEN-style approaches) — **not** a full
   coalescent simulation (no actual genealogy/recombination map), but it
   reproduces realistic local LD and "ancestry tracts" without requiring a
   tool like `msprime`. Genotype = sum of the two haplotype draws (0/1/2
   dosage, standard additive coding).

This was validated by running PCA on the simulated genotype matrix: the
resulting components separate individuals by their true simulated ancestry,
as expected from real genotype data with population structure.

## Self-reported ethnicity model — the part you can tune

This is generated from the **true** ancestry proportions through an
explicit, parameterized process (`simulate_covariates.py`), so the gap
between genetics and self-report is a controlled variable, not an
accident:

- `concordance` (this run: **0.85**) — probability that self-report equals
  the individual's plurality genetic ancestry.
- `mismatch_mode` (this run: **"proportional"**) — when self-report doesn't
  match plurality ancestry, the alternate label is drawn proportional to the
  individual's own admixture vector (so admixed people are more likely to
  report a different component than their plurality one — this is meant to
  mimic real self-report patterns among multi-heritage individuals).
  Alternatives available: `"uniform"` (random other label) and `"adjacent"`
  (biased toward the second-largest ancestry component).
- `allow_multiselect` (this run: **True**) — individuals with a substantial
  second ancestry component (≥ 0.25) may report two categories, similar to
  "two or more races/ethnicities" options on real surveys (UK Biobank, US
  Census).
- `other_rate` (this run: **0.02**) — a small fraction self-report
  "Other/Unknown" regardless of genetics (missing-completely-at-random by
  default here; you can change `simulate_covariates.py` to make this
  ancestry-dependent if you want missing-not-at-random instead, which is
  often more realistic).

Realized rates in this run: self-report matched dominant genetic ancestry
**84.3%** of the time (target was 85%; the gap is sampling noise), and
**30.0%** of individuals multi-selected.

Per-individual **true** ancestry fractions are also retained in
`metadata.csv` (`true_ancestry_frac_*` columns), so you always have ground
truth to compare self-report against — this is the key feature for fairness
analyses: you can measure exactly how much bias is introduced by treating
self-report as a proxy for genetic ancestry, because you know the truth by
construction.

## Covariates

- `age` — uniform over [18, 85] with a small per-population mean shift
  (mimics real cohort recruitment imbalances across groups; this is a
  *sampling* artifact in the simulation, not a biological claim).
- `sex` — uniform M/F, independent of ancestry.
- `phenotype` — a continuous outcome simulated as:
  `phenotype = genetic_component + ancestry_confound + noise`, where the
  genetic component comes from 20 causal SNPs (flagged in `snp_info.csv`,
  `is_causal` / `causal_effect_size` columns) explaining ~30% of variance,
  and the ancestry confound is a **direct, non-genetic** function of true
  ancestry proportions explaining ~15% of variance. This lets you test
  whether a GWAS or PRS pipeline correctly adjusts for population
  stratification (e.g. via PCs or a mixed model) — a naive analysis that
  ignores ancestry will show inflated/confounded SNP associations because
  of the deliberately-injected ancestry confound.

## Regenerating with different parameters

Edit the `sim_cfg` / `cov_cfg` blocks at the top of `run_simulation.py` and
re-run. Key knobs:

```python
SimConfig(
    n_individuals=...,      # cohort size
    n_snps=...,             # number of variants
    n_populations=...,      # number of ancestral source populations
    fst=...,                # population differentiation (0.01=subtle, 0.15=strong)
    admixture_alpha=...,    # Dirichlet conc.: smaller = less admixed/more discrete clusters
    block_size=...,         # LD block size in SNPs
)

CovariateConfig(
    concordance=...,            # self-report vs genetics agreement rate
    mismatch_mode=...,          # "uniform" | "proportional" | "adjacent"
    allow_multiselect=...,
    other_rate=...,
    phenotype_heritability=...,
    phenotype_ancestry_confound=...,
)
```

## Known simplifications (so you don't mistake this for real population genetics)

- No actual recombination map, mutation process, or coalescent genealogy —
  the LD-block model approximates the *statistical signature* of LD and
  admixture tracts, not the underlying biology. If you need true coalescent
  realism (e.g. testing methods sensitive to genealogical structure, rare
  variant sharing, or recombination hotspots), consider `msprime` instead.
- All SNPs are independently assigned chromosome/position; no real genome
  build or known LD map is used.
- Hardy-Weinberg equilibrium is assumed within each population-of-origin
  draw; no inbreeding, relatedness, or family structure is modeled (every
  individual is simulated as founder/unrelated).
- The "Other/Unknown" self-report and age-ancestry shift are simple MCAR /
  linear mechanisms — real-world missingness and recruitment bias are
  usually more structured (MNAR); easy to extend if your use case needs it.

# Simulated genotype + ancestry dataset WITH distribution shift across splits

Generated by `run_simulation_with_shift.py`. Same underlying population-
genetic model as the base dataset (see that README for the genotype/LD/
admixture model details) -- this version additionally generates multiple
named **splits** from a *shared* ancestral structure, with three
independently-controllable ancestry-related shift mechanisms applied
per split.

## What's shared across all splits (so "shift" is meaningful, not arbitrary)

- The same ancestral allele frequencies (`p_pop`) for all 5 populations.
- The same SNP panel (same `snp_info.csv` for every individual regardless
  of split).
- The same 20 causal SNPs and the same BASE effect sizes for those SNPs
  (`causal_base_effect_size` in `snp_info.csv`) -- locked in from the first
  split and reused everywhere.
- The same ancestry-confound coefficients.

Only the *draw* from this shared structure differs by split: who's in the
cohort, how noisy their self-report is, and (optionally) how strongly the
shared causal SNPs actually move the phenotype for them.

## The three shift mechanisms (each independently controllable per split)

### 1. Composition shift — `population_weights`
Controls the relative proportion of each ancestral population in a split's
admixture draws. `[1,1,1,1,1]` = balanced/no shift; `[1,6,1,1,1]` = the
2nd population (European, in this run) dominates. This is the standard way
to simulate, e.g., a European-heavy discovery GWAS cohort vs. a more
diverse validation cohort.

### 2. Label shift — `concordance` / `mismatch_mode`
Same mechanism as the base dataset's self-report generator, but the
`concordance` (how often self-report matches true plurality ancestry) and
`mismatch_mode` (how the mismatched label is chosen) can differ by split.
A split with lower concordance has noisier self-reported ethnicity relative
to the *same underlying genetic truth* -- useful for testing whether a
model that relies on self-report as an ancestry proxy degrades when that
proxy gets worse.

### 3. Causal shift — `population_effect_multipliers`
Scales the shared causal SNPs' effect sizes by an individual's plurality
ancestry. `None` = no causal shift (effects identical for everyone, in
every split). An array like `[0.4, 1.0, 0.4, 0.4, 0.4]` means: full effect
size within population index 1 (European), 40% of that effect size for
everyone else. This simulates real, well-documented trans-ancestry GWAS
effect-size heterogeneity / polygenic score portability decay -- a model
trained where genetic effects look one way will systematically
under/over-predict in a population where the true effect is attenuated.

## This run's configuration

| Split | n | Composition (population_weights) | Concordance | Mismatch mode | Effect multipliers |
|---|---|---|---|---|---|
| `train` | 4,000 | `[1,6,1,1,1]` (European-heavy) | 0.95 (clean) | proportional | none (baseline effects) |
| `test_matched` | 1,000 | `[1,6,1,1,1]` (same as train) | 0.95 | proportional | none |
| `test_shifted` | 1,000 | `[1,1,1,1,1]` (balanced) | 0.70 (noisier) | adjacent | `[0.4, 1.0, 0.4, 0.4, 0.4]` (attenuated outside European) |

`test_matched` is included as a control: it has the SAME composition and
label-noise settings as `train`, so any performance gap between
`test_matched` and `test_shifted` for a downstream model can be attributed
to the deliberately-introduced shift, not just ordinary train/test sampling
noise.

**Realized values from this run** (check `simulation_config.json` ->
`split_summaries` for the authoritative numbers, these will vary slightly
run to run due to sampling):

- `train`: ~67% European dominant ancestry, self-report concordance ~0.93
- `test_matched`: ~68% European, concordance ~0.95 (matches train, as intended)
- `test_shifted`: ~20-22% per population (balanced), concordance ~0.70, and
  noticeably lower phenotype variance from causal SNPs (effect attenuation
  outside European reduces the genetic signal for the now-larger
  non-European share of this split)

## Files

Same structure as the base dataset, plus a `split` column in `metadata.csv`
(`train` / `test_matched` / `test_shifted`) and `individual_id` values
prefixed by split name (e.g. `TRAIN_000001`, `TEST_SHIFTED_000001`).
`genotypes.bed/.bim/.fam` contains all splits concatenated in the same row
order as `metadata.csv`.

| File | Description |
|---|---|
| `genotypes.bed/.bim/.fam` | PLINK fileset, ALL splits combined, `split` column in metadata tells you which rows are which |
| `metadata.csv` | Per-individual: split, demographics, true ancestry, self-report, phenotype |
| `snp_info.csv` | Per-SNP: position, alleles, per-population freq, causal flag + SHARED base effect size |
| `simulation_config.json` | Exact per-split parameters AND realized summary statistics for verification |

## Verifying the shift yourself

```python
import pandas as pd
meta = pd.read_csv("metadata.csv")

# Composition shift: dominant ancestry distribution by split
print(meta.groupby("split")["dominant_genetic_ancestry"].value_counts(normalize=True))

# Label shift: self-report concordance by split
print(meta.groupby("split")["self_report_concordant_with_genetics"].mean())

# Causal shift: regress phenotype on causal SNP dosages, separately by
# split and by ancestry-within-split, and compare fitted effect sizes --
# they should be ~full-strength for the European-plurality group and
# ~40% of that for everyone else, but ONLY in test_shifted.
```

## Defining your own splits

Edit the `SPLITS` list in `run_simulation_with_shift.py`. Each `SplitSpec`
is independent:

```python
SplitSpec(
    name="my_split",
    n_individuals=2000,
    population_weights=[1,1,1,1,1],          # composition shift knob (None = uniform)
    concordance=0.85,                         # label shift knob
    mismatch_mode="proportional",             # "uniform" | "proportional" | "adjacent"
    population_effect_multipliers=None,       # causal shift knob (None = no shift)
                                               # or np.array([...]) length K,
                                               # or np.array([[...]]) shape (n_causal, K)
    seed_offset=3000,                         # keep unique per split
)
```

Add as many splits as you want to the list; all of them will share the same
causal architecture and be concatenated into one combined output with a
`split` column.
